# Plan 0 → 100 — final production project

The percentages below represent project completeness, not account return. `100` means a deployable final system with real execution, settlement, supervision, observability and operating procedures.

## 0–10: constraints and economic model — complete

- Define the only allowed edge: buy a complete YES/NO set below its $1 merge value.
- Reject prediction, leverage, martingale, averaging down and directional exposure as profit mechanisms.
- Model current per-market fee curves rather than using `YES + NO < 1` alone.
- Include order-book depth, minimum order size, stale data and a safety reserve.
- Make the $10→$100/7-day target observational. It cannot weaken risk controls.

Exit gate: the same quote produces the same deterministic decision and all costs are explicit.

## 10–20: current protocol integration — complete

- CLOB V2 SDK and production host.
- Gamma market discovery.
- Dynamic market metadata: fee rate/exponent, minimum order size, tick size, taker delay.
- Standard binary markets only; no NegRisk/combinatorial settlement.
- pUSD and current CTF collateral adapter.

Exit gate: `npm run doctor` reaches current endpoints and finds eligible markets.

## 20–30: real-time market-data plane — complete

- REST seed of both outcome books.
- WebSocket snapshots and incremental changes.
- Reconnect with backoff and heartbeat.
- Normalized sorted books and staleness checks.
- Periodic market-universe refresh.

Exit gate: live books remain coherent through disconnect/reconnect tests.

## 30–40: strategy and sizing — complete

- Walk all ask levels needed for equal YES and NO shares.
- Calculate fees per fill level.
- Evaluate executable quantities around depth boundaries and minimum size.
- Choose the highest absolute expected profit inside available capital.
- Require both minimum net edge and minimum dollar profit.
- Deduplicate/cool down repeated opportunities.

Exit gate: unit tests reject the viral `$0.48 + $0.49` example when fees make it negative.

## 40–50: independent hard-risk plane — complete

- Maximum capital per cycle.
- Maximum market and total open exposure.
- Daily realized-loss stop.
- Consecutive execution-failure stop.
- Supervisor multiplier may only reduce risk.
- Target-capital stop.
- Partial fill always pauses live execution.

Exit gate: neither configuration nor OpenAI can bypass a hard boundary at runtime.

## 50–60: simulation and evidence — complete

- Scanner mode never authenticates or trades.
- Paper broker consumes the same candidates as live mode.
- Virtual capital compounds only from net modeled profit.
- SQLite audit of every candidate, execution and supervisory decision.
- Performance report command.

Graduation requirement before real money:

- At least 24 continuous hours without crashes.
- At least 100 detected candidates, or documented evidence that the market does not offer enough edge.
- Zero accounting inconsistencies.
- Positive paper PnL after configured reserve.
- No stale-book executions.

If these gates fail, live mode is not justified. The correct result may be that the strategy is not economically viable.

## 60–75: live order execution — complete

- Dedicated EOA authentication and optional API-key derivation.
- Two limit BUY orders signed from one market snapshot.
- One batch submission with FOK semantics per leg.
- Before/after conditional-token and collateral reconciliation.
- No blind retries of an unknown order state.
- Cancel outstanding orders during controlled shutdown.

Live capital ladder:

1. `$10`: maximum one cycle at a time; default trade cap `$6`.
2. Remain at `$10` until 25 completed cycles and zero partials.
3. Any partial, unexplained negative reconciliation or API ambiguity returns the system to paper mode.
4. Capital increases are manual operational decisions, never autonomous responses to the seven-day target.

## 75–85: settlement and residual-risk handling — complete

- One-time ERC-1155 approval for the current collateral adapter.
- Direct Polygon merge of equal YES/NO balances.
- Six-decimal amount handling.
- Receipt verification.
- Merge matched inventory even when the requested quantity is not completely obtained.
- Preserve unmatched residual inventory and pause for operator review; never market-buy the missing side without an edge.

Exit gate: a completed cycle ends in pUSD and the measured balance delta matches logged PnL.

## 85–92: OpenAI supervisory agent — complete

- OpenAI Responses API with strict JSON Schema output.
- Reviews statistics, recent errors, candidates and hard-risk state.
- Decisions: `CONTINUE`, `REDUCE_RISK`, `PAUSE`.
- Fail-closed reduction when the API is unavailable.
- The model is not called per quote or per order.
- Prompt explicitly forbids using the target as a reason to raise risk.

Exit gate: malformed/unavailable AI output cannot stop deterministic safety controls from working.

## 92–97: operations and observability — complete

- Structured redacted logs.
- SQLite WAL storage.
- Prometheus process and strategy metrics.
- Local health and status endpoints.
- Docker multi-stage build, Compose and hardened systemd unit.
- Graceful SIGINT/SIGTERM shutdown.

Exit gate: restart preserves audit history and does not leave intended resting orders behind.

## 97–100: final validation and release — complete in repository; environment acceptance remains operator-side

Repository release gates:

- TypeScript strict typecheck.
- Unit tests for fees, depth, strategy, compounding hurdle and risk limits.
- Production build.
- Doctor command.
- Complete configuration and operating documentation.

Environment acceptance gates that cannot be pre-completed without the owner’s wallet and credentials:

- Fund dedicated wallet with `$10` pUSD plus POL gas.
- Confirm geoblock endpoint permits the current runtime location.
- Verify CLOB allowance and one-time merge approval.
- Run the 24-hour paper gate on the deployment machine.
- Execute one minimum-size live cycle while watching reconciliation.

At 100, the software is final. Profit remains market-dependent. No responsible implementation can make a guaranteed seven-day 10× return part of the software acceptance criteria.
